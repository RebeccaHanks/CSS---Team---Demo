View Transitions API Demo

A simple teaching demo for showing how page changes can fade or morph instead of instantly jumping.

1. What the API Does

The View Transitions API takes a snapshot before the page changes, updates the DOM, takes another snapshot, and then animates between them. 

/* ::view-transition pseudo-element tree */
::view-transition
└── ::view-transition-group(root)
    └── ::view-transition-image-pair(root)
        ├── ::view-transition-old(root)
        └── ::view-transition-new(root)

2. Without View Transitions

Without the API, the list view hides and the detail view appears right away. 

// Without view transitions: instant swap
function showDetail(id) {
    document.querySelector('.list-view').hidden = true;
    document.querySelector('.detail-view').hidden = false;
}

3. With View Transitions

With document.startViewTransition(), the same DOM change becomes animated. 

// With view transitions: animated crossfade
function showDetail(id) {
    document.startViewTransition(() => {
        document.querySelector('.list-view').hidden = true;
        document.querySelector('.detail-view').hidden = false;
    });
}

4. Feature Detection

Always check if the browser supports it. If not, just run the normal update. 

function showDetail(id) {
    const update = () => {
        document.querySelector('.list-view').hidden = true;
        document.querySelector('.detail-view').hidden = false;
    };

    if (document.startViewTransition) {
        document.startViewTransition(update);
    } else {
        update();
    }
}

5. Named Elements and the Morph Effect

A view-transition-name lets one element morph into another element. In this demo, a small card turns into the detail panel. 

/* Name the card in the list view */
.card.is-selected {
    view-transition-name: active-card;
}

/* Name the matching container in the detail view */
.detail-header {
    view-transition-name: active-card;
}
function showDetail(cardEl) {
    // Apply the name just before the transition starts
    cardEl.style.viewTransitionName = 'active-card';

    document.startViewTransition(() => {
        // Swap the views
        cardEl.closest('.list-view').hidden = true;
        document.querySelector('.detail-view').hidden = false;

        // Clear the name after DOM update so it doesn't persist
        cardEl.style.viewTransitionName = '';
    });
}

7. Custom Animation CSS

You can change the default fade by styling the view transition pseudo-elements. 

/* Override the default crossfade for the root */
::view-transition-old(root) {
    animation: 200ms ease-in both fade-out;
}

::view-transition-new(root) {
    animation: 300ms ease-out both fade-in;
}

/* Custom slide for a named element */
::view-transition-old(active-card) {
    animation: 300ms ease-in both slide-out-left;
}

::view-transition-new(active-card) {
    animation: 300ms ease-out both slide-in-right;
}

@keyframes fade-out {
    to { opacity: 0; }
}

@keyframes fade-in {
    from { opacity: 0; }
}

8. Cross-Document Transitions

For separate HTML pages, add this to both pages. Chrome and Edge support this, but other browsers may just navigate normally. 

/* Add to both pages that should animate between each other */
@view-transition {
    navigation: auto;
}

9. Reduced Motion

Some users prefer less animation, so we should make the transition almost instant. 

@media (prefers-reduced-motion: reduce) {
    ::view-transition-group(*),
    ::view-transition-old(*),
    ::view-transition-new(*) {
        animation-duration: 0.01ms !important;
    }
}
