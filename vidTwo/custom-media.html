@custom-media Demo Page

A live teaching demo for explaining repeated breakpoints, named media queries, polyfills, and build tooling.

1. The Problem: Repeated Magic Numbers

❌ Hard-Coded Breakpoints 
@media (min-width: 48em)
@media (min-width: 48em)
@media (min-width: 48em)
@media (min-width: 64em)

The same values appear repeatedly across many files. If the breakpoint changes, you must update everything manually.

✅ Named Breakpoints 
@custom-media --medium (min-width: 48em);
@custom-media --large (min-width: 64em);

Define the breakpoint once, then reuse it everywhere. Easier to read and easier to maintain.

2. The Syntax

Define Aliases

@custom-media --medium (min-width: 48em);
@custom-media --large (min-width: 64em);
@custom-media --motion (prefers-reduced-motion: no-preference);

Use Them

@media (--medium) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}

4. Where @custom-media Belongs

In your architecture, custom media definitions belong in: 

tokens/breakpoints.css

Breakpoints are design tokens just like colors and spacing. 

@custom-media --small (min-width: 30em);
@custom-media --medium (min-width: 48em);
@custom-media --large (min-width: 64em);
@custom-media --dark (prefers-color-scheme: dark);

7. Before and After Build Example

Source CSS

@custom-media --medium (min-width: 48em);

@media (--medium) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}

Compiled Output

@media (min-width: 48em) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}
Important Teaching Point: The browser never sees @custom-media. The build tool converts it into regular CSS first.

8. Refactor Workflow

  1. Create tokens/breakpoints.css
  2. Add @custom-media definitions
  3. Import file into main.css
  4. Replace hard-coded breakpoints
  5. Run your build tool
  6. Verify everything still works

Then demonstrate changing one breakpoint value and explain that the entire project updates automatically.
